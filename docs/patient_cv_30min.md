# 30 分钟窗口患者交叉验证实验

本流程先在原 Train 内选择神经网络和训练方案，再用完整 Validation 确定报警阈值，最后对选定方案做一次固定规则的 Test 评价。默认通过 `data.horizons: [6, 3, 2, 1]` 按此顺序运行，每个时距完成全部选定模型后再运行下一时距；`--horizon 6` 可覆盖为单个时距。每次实际训练的配置仍保存独立的整数 horizon，分折、权重、阈值均不跨时距复用。未设置 horizons 时兼容原单个 horizon。体征历史仍为过去 120 分钟。XGBoost 的展平特征、参数、CPU 外存训练、AP 早停和原有校准阈值流程保持原实现，不纳入本次新协议。

## 数据版本与采样

原包保留在 `data/Mutimodel_data/固定训练数据`。新包位于 `data/Mutimodel_data/固定训练数据_30min`。全部配置的数据路径已指向新包；历史结果仍属于原始数据版本，不可直接作为新实验的性能对照。

每次住院按预测时间排序，保留首个窗口，随后保留距上个已保留时点至少 30 分钟的最早窗口。规则不读取标签、距事件时间或结局；有缺口时不插值、不补窗。固定 10 分钟网格上等价于每三个窗口取一个，但实际使用时间间隔，避免缺失时点造成错误。各住院以自身首个可用预测点为相位，不使用全院整点对齐。

Train、Validation、Test 使用相同规则；所有患者和住院均保留，患者归属不变。120 分钟历史、每分钟分辨率、全部模态数值、缺失标记、标签、文书引用均取原始保留行。新 sample_id 连续重编号，`source_sample_id` 保存原行号；split 数组与 shard start/rows 同步重建。不能仅替换 tensors 而沿用旧索引。

|---|---:|---:|---:|---:|
| Train | 842163 | 282653 | 862 | 98 |
| Validation | 313943 | 105254 | 288 | 33 |
| Test | 303524 | 101796 | 235 | 32 |

新包总计 489703 个窗口，保留 6327 名患者、6717 次住院。上述为元数据计数，实际训练/阈值选择还排除无效输入。Validation 阳性患者由 34 降至 33；不根据标签补回丢失的阳性窗口，否则会改变采样机制。30 分钟步长下相邻输入仍重叠约 75%，不能把窗口看作独立样本。

重建命令如下；目标必须不存在，脚本拒绝覆盖源包或已有输出：

```powershell
python resample_cohort.py --source data/Mutimodel_data/固定训练数据 --output data/Mutimodel_data/固定训练数据_30min --minutes 30
```

本机已完成重建，无需重复执行。`resampling_provenance.json` 保存源文件指纹、选中行摘要和前后计数；`resampling_status.json` 必须为 completed。生成时逐字段重读目标 NPZ，与源保留行比较数值及 dtype，随后验证全部目标分片。输出完成前不得用于训练。

## 数据分工和防泄漏边界

1. 原 Train 按患者分 3 折，按当前时距是否存在阳性窗口分层。同一患者所有住院、窗口必须同折。不能按窗口随机分折，也不能按“住院是否曾发生事件”替代当前任务阳性分层。
2. 每折仅在训练患者上拟合标准化，并在其训练部分采样。折内评估保留全部 30 分钟窗口及自然阳性比例。未标准化磁盘缓存可复用，标准化参数不能跨折复用。
3. 每折按目标召回率下最低 FPR 早停。候选比较先看三折 FPR 均值，再看折间标准差；完全并列时看 AP。保存 0.80、0.85、0.90 召回工作点。CV 指标是方案选择统计量，不能作为无偏最终性能。
4. 固定方案后，取三折最佳 epoch 的中位数，非整数时向上取整，在全部 Train 重新初始化并训练固定轮数。不得用完整 Validation 早停或按其指标重新选择架构、采样、种子。
5. 第一轮关闭 Platt。完整 Validation 只选一次阈值。目标为 Recall >= 0.80 时 FP 最小，并列取较高阈值；分类为 score >= threshold。同分样本整体处理。若 288 个阳性窗口全部有效，至少识别 231 个才满足要求。
6. 保存模型制品和阈值后，才访问 Test 张量并计算固定规则性能。Test 上不扫描新阈值，也不按 Test 结果挑选候选。输出患者聚类 bootstrap 的 Recall、Precision、FPR、FP 95% 区间；重采样不重新训练或重选阈值。这些区间条件于已固定模型/阈值，不包含整套开发过程的不确定性。

实际 6h Train 三折的选择部分分别包含 33、33、32 名阳性患者，264、288、310 个阳性窗口。每个训练部分分别有 65、65、66 名阳性患者。各折窗数不同，比较 FPR 而不是直接比较 FP 数量。缺少有效两类样本时明确失败，不借用其他集合。

默认运行自动串联 CV、选模型和最终化。每个时距先完成本次指定的全部候选模型，仅根据这些 Train 内 CV 汇总选择一个模型，再全量 Train 重训、完整 Validation 选阈值、固定规则评价 Test。候选数据版本、患者分折、代码版本或计算预算不同会拒绝自动最终化；任一候选训练失败时保留文件并停止，不使用剩余候选继续选模型。选择规则依次为平均 FPR、折间标准差（均越小越好）、平均 AP（越大越好）；完全并列按模型名，再按摘要路径排序。规则和候选列表在训练前落盘，选择记录在 Test 之前落盘。每个时距仅最终化一个模型，全部未获选候选结果保留。

`--cv-only` 可恢复仅输出 CV 的手动流程。最终化入口绑定 CV 的配置、分区、数据文件版本和代码摘要，拒绝改动后的方案；记录 finalization_started.json，阻止同一 CV 运行意外重复最终化。它不能阻止人工另开实验后反复查看 Test，因此研究管理上仍需预先确定候选集合。失败的最终化请先查看标记指向的日志和是否已生成 Test 报告，不能直接删除标记重试。

原 Test 已用于历史研究；其 30 分钟子集不是一个新的独立外部测试集。如果此前已依据该 Test 选择优化方向，新的结果应标记为历史队列上的进一步研究，最终独立结论仍需要未用于开发的患者队列。任何代码检查都不能恢复已经消耗的测试独立性。

## 神经网络采样和公平对照

新配置 `patient_time_balanced` 每批约 6.25% 阳性，默认 batch 1024，因此每批 64 阳性、960 阴性。优先不同患者；同一患者轮换窗口，并按事件前 0–60、60–180、180 分钟以上的可用时间层轮换。TTE 为已有区间中点近似，只用于 Train 采样，不作为模型输入。其他时距只使用实际存在的时间层。

每轮固定 32 步，共 32768 次抽样，2048 次阳性抽样；单个阳性窗口每轮最多 16 次，超出总可用预算时明确报错。各患者窗口数量差异较大，该上限意味着少窗口患者达到上限后暂时退出，均衡并非无限制重复少量记录。仍需从患者曝光审计判断是否过拟合。

每轮输出 `sampling_epoch_*.json` 和与该折训练 rows 对齐的 `exposure_epoch_*.npy`，保存患者次数、窗口次数、覆盖和最大重复次数。`class_weight` 在均衡采样下必须为 false。验证和测试没有重采样。

公平采样对照使用 `uniform_budget`：相同 batch、steps_per_epoch、最大 epochs、patience、学习率、种子和患者折，均匀随机抽取有效训练窗口，不指定类别比例。`original` 是遍历全队列的历史采样，计算预算不同，比较脚本会将其分组，不能与固定步数实验混为同等预算。难负样本挖掘本轮不启用，避免把多个改动混在一起。

采样间隔变化会改变模型训练分布，也减少部分短时距阳性患者；每个时距应独立审计及训练。当前 1h 的三折训练部分分别有 67、67、70 个阳性窗口，每轮最多允许 1072、1072、1120 次阳性抽样。因此配置通过 `positive_fraction_by_horizon: {1: 0.03125}` 将 1h 每批阳性数设为 32，每轮共 1024 次；其余时距仍为 6.25%。总步数、总抽样量、重复上限均不变。运行配置保存实际生效的单一比例，均匀采样对照仍不使用阳性配额。若更换数据导致有效窗口更少，上限检查仍会明确失败，不能放宽上限掩盖重复过多。

## 8GB GPU 和 32GB 内存设置

默认 CUDA 自动选择 BF16（不支持时 FP16），保留 fused AdamW、锁页内存、非阻塞传输和 GPU 数值预处理。科学对照默认 deterministic=true；没有为吞吐擅自关闭确定性。

本机 PyTorch 2.11.0+cu128 的原生 GRU 层间 dropout 在程序退出时可复现 Windows 错误码 -1073740791。最小程序启用 dropout=0.1 时复现，dropout=0 时正常退出，与是否使用 DataLoader worker 无关。因此两份新研究配置显式设置 `model.rnn_dropout: 0.0`，仅关闭 LSTM/GRU 的层间 dropout，保留投影层 dropout=0.1；TCN/GRU-D 不受这个参数影响。旧配置默认 rnn_dropout=null，继续沿用共享 dropout，没有静默修改历史模型。关闭该层间 dropout 是本轮实验明确记录的环境兼容设置，两个采样实验保持一致。

原始体征使用按原 split 构建的只读 NPY memmap，跨折复用。它保存未标准化的 14 通道和 6 个实测标记，不缓存训练折归一化结果，也不包含将来结局输入。Train 缓存约 2.0 GiB，通过操作系统页缓存复用；训练时不把全部模态和全部分片载入 RAM。两个 CPU worker、每个预取两批，worker 只打开 CPU memmap，避免 Windows spawn 复制全套张量或调用 CUDA。

`benchmark_training.py` 只在 Train 样本上做短时更新，丢弃测量模型，不用于科学方案选择。测试 batch 128–4096 和 worker 数，测量稳态样本/秒及 CUDA allocated/reserved 峰值。CUDA 峰值不包含桌面和驱动占用；还需为系统保留显存。部分短测与回归测试并行，数字仅作吞吐方向参考，不是严格性能排名。

已观察到 worker 预取明显改善 GRU/LSTM 吞吐；TCN 增大到 2048/4096 后收益趋平；GRU-D 由于逐时间步循环，仍比 cuDNN GRU/LSTM 慢，单纯填满显存不能消除该瓶颈。统一 batch 1024 是控制抽样预算和训练更新次数的初始配置，不能承诺所有模型 GPU 利用率持续 100%。若另行调大 batch，必须同步制定步数/学习率方案、重新做 CV，并保持采样对照一致。

## 运行顺序

```powershell
# 1. 元数据审计：含 Train 患者三折，不训练
python main.py --audit-threshold-splits

# 2. 只选 GRU，四个时距依次自动完成 CV、重训、Validation 和 Test
python main.py --models gru

# 只运行 6 小时任务
python main.py --models gru --horizon 6

# 或运行默认完整实验，每个时距四个候选，各三折，只最终评价一个获选模型
python main.py

# 以下是可选的手动研究流程，不是默认自动流程的必需步骤
python main.py --cv-only

# 比较同一协议内的候选，输出路径必须不存在
python compare_cv.py --runs-dir runs/patient_cv_30min --output runs/patient_cv_30min/comparison.json

# 4. 选定一个获选 summary 后最终化；沿用其已冻结配置
python main.py --finalize-cv "runs/patient_cv_30min/cv/gru/<时间戳>/cv_summary.json"

# 默认自动流程的最终结果，按时距提取
python extract_results.py --runs-dir "runs/patient_cv_30min/experiments/patient_cv/<批次时间戳>/h6/final" --output-dir runs/patient_cv_30min/results_h6

# 独立硬件测量，输出路径必须不存在
python benchmark_training.py --models gru --batches 512 1024 2048 --workers 0 2 --output runs/new_benchmark.json
```

均匀采样对照配置为 `configs/patient_cv_30min_uniform.yaml`。比较采样方案时先用 `--cv-only`，并核对 epoch、patience 等可编辑预算一致；比较脚本会将不同预算分组，不自动混合。默认自动入口只比较该次命令指定的模型，不会从历史目录追加其他采样配置。比较不同随机种子时，先在每个固定种子的匹配折内比较，再总结种子间一致性，不能挑 Test 表现最好的种子。

## 自动实验结果保留

每次启动单独建立 `runs/patient_cv_30min/experiments/patient_cv/<批次时间戳>/`，不复用或覆盖旧实验。`experiment_plan.json` 保存候选、时距、配置和选择规则；`experiment_state.json` 保存每个时距的当前阶段、所有候选摘要路径、选择记录路径和最终 artifact 路径，失败时包含错误。批次 `training.log` 汇集子流程日志。

每个时距目录 `h6/`、`h3/`、`h2/`、`h1/` 内，`cv/<模型>/<时间戳>/` 保存所有候选。逐折目录保留 `best.pt`、`last.pt`（包含优化器状态）、`history.json`、`preprocessing.json`、`selection_report.json`、逐窗口 `selection_predictions.csv` 以及采样次数文件。折内预测的阈值仅用于诊断模型选择，不是最终部署阈值。

`model_selection.json` 保存候选排名、获选模型、汇总校验和和不使用 Validation/Test 的标记。`final/<获选模型>/<时间戳>/` 保留重新训练的权重、完整验证阈值、Validation/Test 逐窗口预测与报告、患者 bootstrap 和推理 artifact。中间 CV 结果不会被最终训练替换，也不会因模型未获选而删除。中途失败后不自动继续或恢复，重新启动是一个新实验；已完成时距的 Test 报告仍需按既定研究方案管理。

自动串联改动验证：194 项回归测试通过，另有 1 项独立 Python 命令端到端测试通过。后者在微型固定格式数据上一次启动两个时距，自动生成两个最终 Test 报告，退出码为 0；同时验证候选结果保留、固定排名规则、候选失败停止、不兼容候选拒绝最终化。没有为验证这次改动启动真实队列的完整研究或消耗真实 Test。

`--finalize-cv` 不接受覆盖模型、时距或设备参数。输出目录可以另选。若需要更改训练设置，重新跑 CV。原训练程序仍支持 `configs/train.yaml` 多模态 holdout，以及 `configs/vital_thresholds.yaml` 的旧阈值流程。XGBoost 必须显式使用旧配置入口，例如 `python main.py --config configs/vital_thresholds.yaml --models xgboost`；其输入已改为 30 分钟窗口，但没有改其特征、超参数或训练方法。

## 本轮范围与验证

本轮完成 30 分钟数据包、神经网络患者 CV、固定预算采样对照、独立最终化、最小 FP 阈值、患者 bootstrap 和硬件测量。统计特征、检验增强、XGBoost 调参、难负样本、6–24 小时历史及复杂多模态优化暂未加入。

新增测试验证标签盲采样、所有模态原值保留、患者折隔离、逐折统计拟合、缓存值一致、阳性重复上限、CV 禁止读取原 Validation/Test 标签、最终模型保存后才测试、数据变动拒绝最终化、制品重载及固定阈值 bootstrap。运行全套测试：`python -B -m pytest -q -p no:cacheprovider`。

2026-11-17 本机实际验证：全套 175 项测试通过，耗时约 94 秒；真实 30 分钟队列的 GRU 三折各训练一轮、每轮 32 步全部完成，进程退出码为 0，各折的阳性窗口重复次数均不超过 16。该短程运行位于 `runs/smoke_patient_cv_safe`，只用于验证数据流、GPU、采样和 CV，未访问原 Validation/Test 做评价，不应将其当作正式模型选择结果。GRU/LSTM 在兼容配置下的独立硬件测量也正常退出。未运行完整 50 轮四模型研究，未最终化真实 Test。

窗口召回不等于患者/事件检出率，窗口 FP 不等于每患者每天报警数。当前仍缺完整事件/监测暴露契约，因此不输出伪造的报警次数或预警提前量。保留完整 Validation 可减少阈值样本拆分，但其高召回点估计不保证在新患者上达到同一召回率。
